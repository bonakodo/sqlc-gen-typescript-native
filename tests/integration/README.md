# Integration tests

Run from the repository root:

```sh
npm run integration
```

The runner builds the WAT sources, then uses stock sqlc to generate TypeScript
with the raw and optimized WASM plugins. Node tests compare every generated byte
across all supported driver/runtime combinations, SQLite value types, and options
for nulls, query factories, enums, embedded models, overrides, and custom JSON
types. A separate request covers 100 tables, 800 queries, and 202 overrides.
Negative codec tests check that write-only queries reject a mismatch between a
declared argument type and its encoder.

Compact-output tests check that queries in separate SQL files share encoders
and decoders without mixing nullability, custom codecs, or error context. They
also check runtime pruning and queries with no arguments. A repeated-shape
fixture with 100 tables and 800 queries must stay below 700,000 generated bytes;
v0.3.0 produced 1,922,028 bytes for that fixture.

Install Node.js 26, run `npm ci` from the repository root, and install
stock sqlc and the WABT/Binaryen tools with `tools/setup-sqlc.sh` and
`npm run tools`. Set `SQLC` to select a sqlc executable. The root lockfile pins
tooling and integration dependencies; Bun's install hook selects its platform
binary.

Statement-cache runtime tests cover node:sqlite and bun:sqlite. They check
limits, nested calls, cleanup failures, and closed connections. The binding suite checks that fixed encoder calls validate
before execution, including after inlining their single-use locals. Stable-name
tests insert unrelated queries and exercise a real hash collision.

The ignored `.generated/` directory holds generated modules for inspection. Run
the generation suites after `npm run build` to test generation alone:

```sh
node --test --test-concurrency=1 tests/integration/generate_test.ts \
  tests/integration/large_schema_test.ts tests/integration/codec_types_test.ts \
  tests/integration/compact_output_test.ts
```

TypeScript checks the outputs with strict unused-variable, optional-property, indexed
access, and module-syntax settings. TypeScript 6 separately checks Node and Bun
outputs against pinned driver declarations. Runtime tests execute
`better-sqlite3`, `node:sqlite`, and `bun:sqlite` in memory. The same
`node:sqlite` suite runs on Node 26 and Bun 1.4.2, checking both
generated runtime targets, synchronous queries, all query commands, bigint
and blob values, codecs, cache reuse, optional statement cleanup, and reopening
a connection after cache cleanup. The native Bun suite also checks positional
rows with duplicate names, explicit finalization, native transaction rollback,
and both close modes. Bun-only output uses a separate TypeScript config.
The generation tests use Node.js 26 as their test runner. Node and Bun run the
generated SQLite and server modules; server stubs check SQL, bound values,
results, counts, and errors. The ergonomics fixtures cover named codecs, omitted
nullable inputs, null results, bound factories, transactions, and
aggregate/expression metadata. The tests in `../runtime/` check support modules
produced by the actual WASM generator. Run those on Node with `npm run runtime`; it
builds and prepares its own SQLite, pg, and postgres.js modules without an
installed sqlc.

Run `npm run live` after the integration suite to test real PostgreSQL and
MySQL drivers. Supply dedicated test databases with `SQLC_LIVE_PG_URL` and
`SQLC_LIVE_MYSQL_URL`, or use the localhost `sqlc_test` defaults in
`server_live_test.ts`. These tests create and drop fixture tables. The runner
builds fresh WASM, generates and type-checks the live fixtures, and tests CRUD,
rollback, JSON/null, arrays, geometry, placeholders, slices, and BIGINT values.
It does not start database services. CI provides PostgreSQL 17 and MySQL 8.4.
