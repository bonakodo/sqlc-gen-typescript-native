# Integration tests

Run from the repository root:

```sh
deno task integration
```

The runner builds the WAT sources, then uses stock sqlc to generate TypeScript
with the raw and optimized WASM plugins. Deno tests compare every generated byte
across all 13 driver/runtime combinations and options for native SQLite types,
nulls, query factories, enums, embedded models, overrides, and custom JSON
types. A separate request covers 100 tables, 800 queries, and 202 overrides.
Negative codec tests check that write-only queries reject a mismatch between a
declared argument type and its encoder.

Install stock sqlc, Deno, Node, npm, and the WABT/Binaryen tools from
`deno task
tools`. Set `SQLC` to select a sqlc executable. The runner installs
pinned test dependencies with `npm ci`; Bun's install hook selects its platform
binary. These packages only test generated TypeScript and do not build the
plugin.

The ignored `.generated/` directory holds generated modules for inspection. Run
the generation suites after `deno task build` to test generation alone:

```sh
deno test --config tests/integration/deno.json --allow-read --allow-write \
  --allow-env=SQLC --allow-run tests/integration/generate_test.ts \
  tests/integration/large_schema_test.ts tests/integration/codec_types_test.ts
```

Deno checks the outputs with strict unused-variable, optional-property, indexed
access, and module-syntax settings. TypeScript 6 separately checks Node and Bun
outputs against pinned driver declarations. Runtime tests execute
`@bonakodo/sqlite` and `better-sqlite3` in memory. Node and Bun run the
generated SQLite and server modules; server stubs check SQL, bound values,
results, counts, and errors. The ergonomics fixtures cover named codecs, omitted
nullable inputs, null results, bound factories, transactions, and
aggregate/expression metadata. The tests in `../runtime/` check support modules
produced by the actual WASM generator. Run those with `deno task runtime`; it
builds and prepares its own SQLite, pg, and postgres.js modules without an
installed sqlc.

`deno.json` maps `@bonakodo/sqlite` to the published
`jsr:@bonakodo/sqlite@0.1.0` package. Set `DENO_SQLITE_PATH` to an absolute path
to an installed SQLite library. For Homebrew SQLite on macOS:

```sh
export DENO_SQLITE_PATH="$(brew --prefix sqlite)/lib/libsqlite3.dylib"
```

Linux and Windows use an installed `.so` or `.dll` path. The package needs
environment and FFI access; it does not download a library. CI installs SQLite
and sets this path. CI also regenerates and checks `examples/deno-sqlite`.

Run `deno task live` after the integration suite to test real PostgreSQL and
MySQL drivers. Supply dedicated test databases with `SQLC_LIVE_PG_URL` and
`SQLC_LIVE_MYSQL_URL`, or use the localhost `sqlc_test` defaults in
`server_live_test.ts`. These tests create and drop fixture tables. The runner
builds fresh WASM, generates and type-checks the live fixtures, and tests CRUD,
rollback, JSON/null, arrays, geometry, placeholders, slices, and BIGINT values.
It does not start database services. CI provides PostgreSQL 17 and MySQL 8.4.
