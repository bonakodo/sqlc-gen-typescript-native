# Integration tests

Run from the repository root:

```sh
make integration
```

The script needs Go, stock sqlc, Deno, Node, and npm. Set `GO` or `SQLC` to use an
explicit executable. It installs pinned test dependencies with
`npm ci`; Bun's install hook selects its platform binary.
None of those packages take part in the Go library or plugin build.

`deno.json` maps `@bonakodo/sqlite` to the published
`jsr:@bonakodo/sqlite@0.1.0` package. Set `DENO_SQLITE_PATH` to an absolute
SQLite shared library path. On macOS with Homebrew SQLite:

```sh
export DENO_SQLITE_PATH="$(brew --prefix sqlite)/lib/libsqlite3.dylib"
```

On Linux or Windows, use the installed `.so` or `.dll` path. The package needs
environment access and unrestricted FFI; it does not download a library.
CI installs the system SQLite library and sets its path before running tests.

The Go test builds both plugin entry points and passes the same fixtures through
stock sqlc's process and WASI hosts. It compares all generated bytes for the 13
supported driver/runtime combinations and additional options. It keeps the
files in the ignored `scripts/.integration` directory for inspection.

Deno checks all outputs with strict unused-variable, optional-property, indexed
access, and module-syntax settings. The TypeScript 7 Go compiler separately
checks Node and Bun outputs against real, pinned driver declarations. Runtime
tests include the SQLite and server conversion suites. They execute `@bonakodo/sqlite`
and `better-sqlite3` in memory and test PostgreSQL and MySQL calls with small
driver stubs. Node and Bun both execute the SQLite and driver-call tests; the
Go suite also checks that their generated modules match byte for byte. The stubs
check SQL, bound values, results, counts, and errors.

To run just the Go protocol tests:

```sh
SQLC_TEST_INTEGRATION=1 go test ./internal/endtoend -count=1 -v
```

Ordinary `go test ./...` skips this opt-in suite with a clear reason.

To run only the embedded TypeScript runtime suites, use `make runtime`.
The checked-in Deno example output is regenerated and checked in CI.

For real server coverage, run `make live` after `make integration`. Supply dedicated
PostgreSQL/MySQL test databases with `SQLC_LIVE_PG_URL` and
`SQLC_LIVE_MYSQL_URL`, or use the localhost `sqlc_test` defaults in
`server_live_test.ts`. These tests create and drop fixture tables. The script
builds fresh WASM, runs stock sqlc, checks the live fixtures with TypeScript 7,
and runs CRUD, rollback, JSON/null, array/geometry, placeholder, slice, and
BIGINT tests against all three server drivers. CI provides PostgreSQL 17 and
MySQL 8.4 services; the local script does not start database services.
